Hash File Setup & Format Identification

Downloading the Alamo corporate hash file and understanding the NTLM format: why it’s weak and why attackers love finding Windows credential stores.

Why It Matters

Understanding hash formats is fundamental to password security assessment. NTLM is a legacy Windows authentication protocol that stores passwords as unsalted MD4 hashes. “Unsalted” means identical passwords produce identical hashes, making rainbow table attacks trivially effective. This is why penetration testers celebrate when they find NTLM in an environment.

  1. Download alamo-corp-hashes.txt: click here to download
  2. Create a working directory:
    mkdir ~/lab4 && cd ~/lab4
  3. Move the hash file to your working directory
  4. Examine the file contents:
    cat alamo-corp-hashes.txt
    What this does

    Concept: cat displays the full contents of a file. Here you’re examining the hash file to understand its format before attacking it.

    In your output: You should see 8 lines in pwdump format: username:UID:LM_hash:NTLM_hash:::. The NTLM hash is the FOURTH field, a 32-character hexadecimal string: no salt, no algorithm identifier, just the raw hash. Look at the third field: it is aad3b435b51404eeaad3b435b51404ee on every account, the well-known value for an empty LM hash. That tells you Alamo has legacy LM password storage disabled, which is worth recording as a positive finding.

  5. Count the total hashes:
    wc -l alamo-corp-hashes.txt
    What this does

    Concept: wc -l counts the number of lines in a file. In a real engagement, you’d use this to scope the attack: knowing how many accounts you’re targeting helps estimate the time and resources needed to crack them all.

  1. Verify the rockyou.txt wordlist is available and check its size:
    wc -l /usr/share/wordlists/rockyou.txt
    What this does

    Concept: wc -l counts lines in a file. The rockyou.txt wordlist contains over 14 million leaked passwords from a real 2009 data breach. It’s the most commonly used wordlist in password auditing because it represents actual human password choices.

    In your output: You should see approximately 14,344,391 lines. If you get a “No such file” error, the wordlist is still compressed. Run sudo gunzip /usr/share/wordlists/rockyou.txt.gz first.

John the Ripper Attack

Using John the Ripper to crack NTLM hashes with the rockyou.txt wordlist. John is a versatile, CPU-based password cracker that automatically detects hash formats.

Why It Matters

John the Ripper has been the industry standard for password auditing since 1996. It’s preinstalled on every security distribution and supports hundreds of hash formats. Understanding John’s workflow (format detection, wordlist selection, and result retrieval) is fundamental pentesting knowledge.

“Start with the wordlist. If that fails, OSINT is your friend. Don’t brute force. Think like the user. People are predictable. Sports teams, kids’ names, graduation years. The password is usually simpler than you expect.”

Maya Rodriguez
Senior Penetration Tester, NEXUS Security
  1. Navigate to your working directory:
    cd ~/lab4
  2. Run John the Ripper with the rockyou wordlist against the NTLM hashes:
    john --wordlist=/usr/share/wordlists/rockyou.txt --format=NT alamo-corp-hashes.txt
    What this does

    Concept: john is John the Ripper, one of the most widely used password cracking tools. The --wordlist flag tells it to try every password in the rockyou.txt dictionary (14 million+ real leaked passwords). The --format=NT flag specifies that these are NTLM hashes.

    In your output: Watch for lines showing cracked passwords as they’re found. John will display the username and plaintext password for each successful crack. Note the speed. NTLM hashes crack extremely fast because the algorithm was never designed to resist offline attacks.

  3. Check status if John is still running:
    john --status
    What this does

    Concept: The --status flag queries a running John session and reports progress: how many passwords have been tested, the current speed, and estimated time remaining. This is useful when an attack takes longer than expected. John doesn’t print H/s. Press any key while it runs (or run john --status) and its status line shows four rates: g/s (passwords cracked per second), p/s (candidate passwords tried per second), c/s (hashes computed per second) and C/s (candidate and hash combinations per second). Record c/s: hashes computed per second is John’s equivalent of Hashcat’s H/s.

  1. Display all cracked passwords:
    john --show --format=NT alamo-corp-hashes.txt
    What this does

    Concept: The --show flag tells John to display all previously cracked passwords from its potfile (~/.john/john.pot). John stores results persistently so you can retrieve them later without re-running the attack.

    In your output: You should see each cracked account listed as username:password followed by a summary line showing how many were cracked out of the total. Record these; you’ll need them for your results table.

  1. Examine John’s potfile to see how cracked passwords are stored:
    cat ~/.john/john.pot
    What this does

    Concept: John stores every cracked password in a plain-text potfile at ~/.john/john.pot. This is why --show works after an attack completes. It reads from this file. On a real engagement, the potfile is a sensitive artifact that must be secured.

    In your output: You should see lines in hash:password format. Compare this to the --show output: --show maps hashes back to usernames, while the potfile stores raw hash-to-password pairs.

Hashcat Attack

Using Hashcat to crack the same NTLM hashes with GPU acceleration (or CPU fallback). Hashcat is the modern standard for high-speed password recovery.

Why It Matters

Hashcat leverages GPU parallel processing for dramatically faster cracking speeds. On modern hardware, Hashcat can test billions of NTLM hashes per second, compared to millions with CPU-only tools. Understanding both John and Hashcat gives you flexibility for different assessment scenarios.

  1. Extract raw NTLM hashes for Hashcat (it needs the hash alone, not the full pwdump line):
    cut -d':' -f4 alamo-corp-hashes.txt > alamo-corp-hashes-only.txt
    What this does

    Concept: cut splits each line on a delimiter and extracts specific fields. Here, -d':' sets the colon as the delimiter and -f4 grabs the fourth field. Always check the layout before you cut: this file is pwdump format, username:UID:LM_hash:NTLM_hash:::, so field 2 is the numeric UID and field 3 is the LM hash. The NTLM hash you want is field 4. Unlike John, which reads the whole pwdump line, Hashcat expects the hash alone with nothing else on it.

    In your output: The > redirects the output to a new file. Verify with cat alamo-corp-hashes-only.txt. You should see only 32-character hex strings, one per line, with no usernames.

  2. Verify the extraction:
    cat alamo-corp-hashes-only.txt
    What this does

    Concept: cat prints the file you just created. This is the capture Hashcat’s input format screenshot is taken from.

    In your output: You should see only 32-character hex strings, one per line, with no usernames, UIDs, or colons. That confirms the NTLM hashes were extracted cleanly for Hashcat.

  1. Run Hashcat with a dictionary attack against the NTLM hashes:
    hashcat -m 1000 -a 0 alamo-corp-hashes-only.txt /usr/share/wordlists/rockyou.txt -D 1
    What this does

    Concept: Hashcat is a GPU-accelerated password cracker. -m 1000 sets the hash mode to NTLM. -a 0 selects a straight dictionary attack (try each word as-is). -D 1 forces CPU mode since VMs typically lack GPU passthrough.

    In your output: Watch for the Speed.#1 line showing hashes per second (H/s). Even in CPU mode, NTLM speeds are remarkably high. Compare this number to John’s c/s rate from Checkpoint 2. This comparison is critical for your engagement report.

  1. Display all cracked results:
    hashcat -m 1000 alamo-corp-hashes-only.txt --show
    What this does

    Concept: Like John, Hashcat stores cracked results in a potfile (~/.local/share/hashcat/hashcat.potfile). The --show flag displays all previously cracked hashes matched against your input file. The output format is hash:password. Note this is reversed from John’s username:password format. Record these results for your comparison table.

  1. Examine Hashcat’s potfile to compare storage format with John:
    cat ~/.local/share/hashcat/hashcat.potfile
    What this does

    Concept: Hashcat stores cracked passwords in its own potfile at ~/.local/share/hashcat/hashcat.potfile. Both John and Hashcat use potfiles, but they store them in different locations with slightly different formats. Knowing where each tool keeps its results is essential for engagement documentation.

    In your output: You should see hash:password pairs. Compare this to John’s potfile. Both store the same data but in different directory locations. This is why deleting potfiles is sometimes necessary when re-running attacks.

warning
  • No GPU in VM: That’s fine! Use -D 1 to force CPU mode. Speed will be lower but still works.

  • Potfile already has results: Hashcat skips already-cracked hashes. Use --potfile-disable to ignore the potfile.

Results Analysis & Documentation

Compiling your cracking results into a structured format for your Unit 3 engagement report. Documenting which passwords cracked, which survived, and why.

Why It Matters

Professional security assessments require clear, reproducible documentation. Clients need to know which accounts are vulnerable, why they’re vulnerable, and what to do about it. The analysis you document now becomes the foundation of your Module 4 Engagement Packet.

  1. Create a results table documenting all 8 accounts (cracked or not)
  2. For cracked passwords, note the plaintext and how long it took
  3. For uncracked passwords, mark as “survived rockyou.txt”
  4. Analyze patterns: What made the cracked passwords weak?
  5. Document your tool comparison (John vs. Hashcat speeds)
  6. Save all notes; you’ll need them for EP 4

Both Sides of the Shield
security
What Red Team Learns
  • Credential Access: NTLM hashes are a penetration tester’s goldmine: fast to crack and often lead to lateral movement
  • OSINT Enhancement: Dictionary attacks are step one. OSINT-informed wordlists dramatically improve success rates against targeted accounts
  • Tool Efficiency: Knowing when to use John vs. Hashcat depends on the scenario; both belong in your toolkit
security
What Blue Team Learns
  • Defense in Depth: NTLM is architecturally weak. Defenders must compensate with MFA, monitoring, and credential hygiene programs
  • Password Policy Design: Complexity requirements alone don’t stop OSINT-informed attacks. Passphrases and blocklists matter more
  • Credential Monitoring: If attackers can extract hashes, you’ve already lost. Focus on preventing initial access and detecting extraction
sync_alt
The Purple Team Connection

Password cracking bridges offense and defense perfectly. Attackers use these tools to exploit weak credentials: the same tools defenders use to audit password strength proactively. Understanding cracking speeds informs both attack timelines and defensive response windows. A password that cracks in seconds requires different defensive controls than one that takes hours. This is why both red and blue teams need hands-on cracking experience.
