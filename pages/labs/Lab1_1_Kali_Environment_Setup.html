Choose and Install Your Hypervisor

Choosing the hypervisor that fits your computer, with an AI assistant’s help, and installing it.

Why It Matters

Virtual machines allow you to run a complete operating system inside your existing OS. This is how security professionals maintain isolated environments for testing tools, malware analysis, and client engagements without risking their primary system.

warning
Your Computer Comes First

The Information Systems and Cybersecurity department requires you to own a laptop that meets its minimum device requirements. Every lab in this course runs on the VM you build here, so check your computer against that page before you start. If you don’t have access to a suitable machine, start with the options on that page, including the one-time financial aid adjustment for technology, and email me right away at john.newsom@utsa.edu so we can get you sorted as soon as possible. Don’t wait until the lab is due.

error
What Your VM Has to Be

Whichever hypervisor you use, your Kali VM has to meet every one of these. They are the same for everyone.

  • Kali image: the official installer for your processor: amd64 for Intel or AMD, arm64 for Apple silicon (Checkpoint 2).
  • Memory: 4 GB minimum, 8 GB recommended if your computer can spare it.
  • Processor cores: 2 or more.
  • Disk: 80 GB, dynamically allocated (it grows as it fills).
  • OS type, if your hypervisor asks: Linux, Debian 64-bit (ARM64 on Apple silicon).
  • Networking: NAT. Parallels and UTM call it Shared Network.
  • VM name and hostname: your abc123.
  • Kali account: username kali, password kali (Checkpoint 4).

lightbulb
Trust the Source, Not the AI

An AI answer is a summary of what it has read, and it can be out of date or simply wrong while sounding completely sure. Prices change, supported chips change, menus get renamed. The source of truth is the original: the vendor’s official page, the tool’s documentation or man page, the standard itself, and in this course, the lab sheet. So use AI to get pointed in the right direction and to understand what you’re reading, then read the source and go by what it says. This is a habit analysts live by: nothing goes in a report because an AI said so, only because you checked it. In your EP 1 Runbook VM setup entry, next to Screenshot 01, name the official page you checked and anything the AI got wrong. That’s also the kind of example the AI Methodology Reflection asks for.

Your hypervisor, your computer, your setup. Download Kali Linux ISO

Downloading the Kali Linux installer image (~4GB) from the official source.

Why It Matters

Kali Linux is a Debian-based distribution designed specifically for penetration testing and security auditing. It comes pre-loaded with hundreds of security tools that you'll use throughout the semester for both offensive and defensive work.

  1. Navigate to kali.org/get-kali
  2. Select Installer Images
  3. Choose the correct architecture: 64-bit (amd64) for Intel/AMD processors, arm64 for Apple Silicon Macs (M1/M2/M3/M4). This depends on your processor, not your hypervisor.
  4. Download the ISO file (approximately 4GB)
  5. Note the download location; you'll need this for the next checkpoint

What You Should Have

A file named something like kali-linux-2024.x-installer-amd64.iso in your Downloads folder.

lightbulb

Start this download before working on other tasks. A 4GB download can take 10-30 minutes depending on your connection. You can proceed to review the remaining checkpoints while it downloads.

warning
  • Wrong architecture: Download the amd64 (64-bit) version unless you have Apple Silicon
  • Unofficial sources: Only download from kali.org; third-party ISOs may contain malware
  • Interrupted download: If download fails, delete partial file and restart; don't resume corrupted downloads

Create and Configure VM

Creating your virtual machine in the hypervisor you chose, to the requirements in Checkpoint 1.

Why It Matters

Proper VM configuration affects performance, stability, and functionality. The VM name is especially important. It appears in your terminal prompt and must be visible in screenshots for assignment verification.

  1. Copy the Tailor it to my setup prompt from the AI Assist card below into your AI assistant, fill in your computer and the hypervisor you chose, and send it. Keep its steps open while you work.
  2. Create a new VM. Name your VM with your abc123, the ID you use to log into Canvas (for example, aaa000), not your Banner ID number. Just the ID: no prefix, no spaces.
  3. If your hypervisor asks for the OS type: Linux, Debian 64-bit (ARM64 on Apple silicon).
  4. Memory: 4 GB minimum, 8 GB recommended.
  5. Processor cores: 2 or more.
  6. Virtual disk: 80 GB, dynamically allocated.
  7. Networking: NAT (Shared Network in Parallels and UTM).
  8. Attach the Kali ISO from Checkpoint 2 as the VM’s startup disk (its CD/DVD drive).
  9. Before you start the VM, check every setting against the requirements in Checkpoint 1. Where the AI’s steps differ from them, the requirements win.
error
Critical: VM Naming Convention

Name your VM <your abc123>, the ID you use to log into Canvas (for example, aaa000), not your Banner ID number. During the install you give Kali the same name as its hostname, so your abc123 shows in your terminal prompt (kali㉿aaa000) and in the VM window’s title bar. That is what verifies the screenshots are your own work; a VM named anything other than your ID makes your screenshots unverifiable.

Install Kali Linux

Running the Kali Linux installer inside your virtual machine to create a functional security testing environment.

Why It Matters

Kali Linux comes pre-loaded with hundreds of security tools. A proper installation ensures all tools work correctly and the system is stable for the entire semester.

  1. Start the VM in your hypervisor
  2. Select Graphical Install from the boot menu
  3. Choose your language, location, and keyboard layout
  4. Set the hostname to your abc123, exactly the same as your VM name (for example, aaa000). No prefix.
  5. Leave domain name blank
  6. Create the user account. Full name: kali. Username: kali. Password: kali (you type it twice).
    What this does

    Concept: Yes, on purpose. We are building this for training, not production. Throw-away credentials are appropriate in a throw-away environment, and a VM you cannot log into is worth nothing to you. Every semester someone forgets the password they invented and has to rebuild the VM. Install and Verify Docker

Installing Docker, the containerization platform we'll use to deploy vulnerable lab targets throughout the course.

Why It Matters

Docker lets us spin up isolated, vulnerable systems safely. Each module's client engagement uses Docker containers. Without it, you can't complete the labs.

  1. Update your package lists
    sudo apt update
    What this does

    Concept: apt update refreshes the list of available packages from the repositories. It does not install anything. It just checks what's available. Always run this before installing new software so you get the latest versions.

  2. Upgrade all installed packages to current versions
    sudo apt full-upgrade -y
    What this does

    Concept: full-upgrade installs the newest versions of everything already on the system. Kali is a rolling release, so your ISO is a snapshot frozen at build time. This step brings your tools up to current. Use full-upgrade rather than plain upgrade: full-upgrade is allowed to add or remove packages to resolve dependency changes, so nothing gets held back. This is why your tool versions will match what the labs and quizzes expect.

  3. Install Docker and Docker Compose
    sudo apt install -y docker.io docker-compose
    What this does

    Concept: apt install downloads and installs packages. The -y flag automatically answers "yes" to the confirmation prompt. docker.io is the container engine; docker-compose lets you define multi-container environments in a single file.

  4. Enable Docker to start automatically and start it now
    sudo systemctl enable docker --now
    What this does

    Concept: systemctl enable tells the system to start Docker automatically on every boot. The --now flag also starts it immediately so you don't have to reboot first.

  5. Add your user to the Docker group
    sudo usermod -aG docker $USER
    What this does

    Concept: usermod -aG appends your user to a group. By default, Docker commands require root access. Adding yourself to the docker group lets you run Docker without sudo every time.

  6. Log out of Kali and log back in (or reboot the VM) so the group change takes effect
    What this does

    Concept: Your group memberships are read when you log in, so the terminal you already have open does not know you joined the docker group. Until you log out and back in, Docker commands without sudo fail with a permission error.

  1. Check the Docker version
    docker --version
    What this does

    In your output: You should see the installed Docker version number. If you get "command not found", the installation didn't complete correctly.

  2. Run the Docker test container
    docker run hello-world
    What this does

    Concept: docker run pulls an image from Docker Hub and runs it as a container. The hello-world image is a tiny test container that prints a success message. If you see "Hello from Docker!", Docker is fully working.

    In your output: You should see "Hello from Docker!" followed by a short explanation of what Docker just did. If you get "permission denied while trying to connect to the Docker daemon socket", you haven't logged out and back in since adding yourself to the docker group. Do that, then run this command again.

System Verification

Running a series of commands to verify your environment is properly configured and all required tools are available.

Why It Matters

Catching configuration issues now prevents frustration later. A working baseline environment means you can focus on learning security concepts instead of troubleshooting setup problems.

Part A: System Information

  1. Display your hostname
    hostname
    What this does

    In your output: This should show your abc123 (for example, aaa000). If it shows kali, the word abc123, or any name that isn’t your ID, fix it before proceeding.

  2. Display kernel and OS information
    uname -a
    What this does

    Concept: uname -a prints all system information: kernel name, hostname, kernel version, architecture. The -a flag means "all." This is a standard first step when documenting an engagement environment.

Part B: Network Connectivity

  1. Display your network interfaces and IP addresses
    ip addr
    What this does

    Concept: ip addr lists all network interfaces and their assigned IP addresses. Look for your eth0 interface. It should have an IP address from your hypervisor’s NAT network (the range depends on the hypervisor; VirtualBox uses 10.0.2.x).

  2. Test internet connectivity
    ping -c 3 8.8.8.8
    What this does

    Concept: ping sends ICMP echo requests to test network reachability. The -c 3 flag limits it to 3 packets. 8.8.8.8 is Google's public DNS. If all 3 packets come back, you have internet connectivity.

Part C: Security Tools

  1. Verify Nmap is installed
    nmap --version
    What this does

    Concept: Nmap is the industry-standard network scanner. You'll use it heavily starting in Module 1 Lab 2. The --version flag confirms it's installed and shows the version number.

  2. Verify Wireshark is installed
    wireshark --version
    What this does

    Concept: Wireshark is a packet capture and analysis tool. You'll use it in Module 3 to inspect network traffic.

  3. Verify John the Ripper is installed
    john --help | head -5
    What this does

    Concept: John the Ripper is a password cracking tool you'll use in Module 4. The | head -5 pipe takes the first 5 lines of output, enough to confirm it's installed without flooding your terminal.

Part D: Docker

  1. Confirm Docker version
    docker --version
  2. Verify no containers are running yet
    docker ps
    What this does

    Concept: docker ps lists running containers. Right now it should show an empty table (just headers). In later modules, this is how you'll confirm your lab target containers are running before you start scanning.

  • Isolated Attack Platforms: Virtual machines let attackers operate from a clean, disposable environment. After an engagement, the VM can be rolled back or deleted, leaving no artifacts on the analyst’s host.
